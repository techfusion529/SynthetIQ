## Step 2 — Fixes applied

### Finding 1: HashChain missing tenant scope
**File**: `worker/src/activities/agent_activities.py` line 363  
**Before**: `chain = HashChain()`  
**After**: `chain = HashChain(org_id=org_id, plant_id=plant_id)`  
**Effect**: GENESIS seed is now `SHA-256("GENESIS:{org_id}:{plant_id}")` — unique per tenant/plant, preventing cross-tenant chain forgery.

### Finding 2: `po["po_number"]` KeyError on every settlement
**File**: `worker/src/activities/agent_activities.py` — `POResult` model  
**Before**: `POResult` had `po_id` but no `po_number` field; Pydantic silently dropped the key set by `result.setdefault("po_number", ...)`.  
**After**: Added `po_number: str = ""` to `POResult`. The `result.setdefault` line already sets it before `POResult(**result)`, so `model_dump()` now includes `po_number`. Both `SettlementDispatchWorkflow` and `MasterEPRComplianceWorkflow` access `po["po_number"]` which is now present.

### Finding 3: GSTIN regex missing word boundary
**File**: `worker/src/agents/privacy.py` line 17  
**Before**: `r"[0-9]{2}[A-Z]{5}[0-9]{4}[A-Z]{1}[1-9A-Z]{1}Z[0-9A-Z]{1}"`  
**After**: `r"(?<![A-Z0-9])[0-9]{2}[A-Z]{5}[0-9]{4}[A-Z]{1}[1-9A-Z]{1}Z[0-9A-Z]{1}(?![A-Z0-9])"`  
**Effect**: Negative look-arounds prevent matching GSTINs embedded in longer alphanumeric tokens. A compound token like `27AAACH1234F1Z5EXTRA` no longer partially matches (the look-ahead `(?![A-Z0-9])` fails because `5` is followed by `E`), so the whole token is not redacted and the suffix is not left dangling. Standalone GSTINs surrounded by non-alphanumeric delimiters continue to be redacted correctly.
